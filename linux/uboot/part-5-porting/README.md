# 移植到真实硬件

QEMU 能帮你理解 U-Boot 的通用机制，但真实开发板会把问题变得更具体：启动 ROM 从哪里读第一段代码？DRAM 谁来初始化？是否需要 TF-A、OP-TEE 或 OpenSBI？U-Boot proper 是直接运行，还是先由 SPL 加载？

本部分不绑定某一块具体开发板，而是教你建立移植 U-Boot 的工作框架。后续你拿到任意一块板子，都可以按这个框架收集信息、阅读源码、构建镜像、烧录验证和排查问题。

真实硬件操作前请准备串口线、稳定电源、原厂恢复镜像和可回滚方案。不要在没有备份的情况下擦写启动介质。

本部分的关键词是“确认”。不要凭经验猜启动偏移，不要把另一块板子的镜像直接烧到当前板子，也不要在没有 recovery 方案时修改板载 flash。真实硬件移植的速度，往往取决于前期信息收集是否扎实。

学完本部分后，你应该能够：

- 画出目标板的启动链。
- 判断是否需要 SPL、TF-A、OP-TEE 或 OpenSBI。
- 找到相近板级配置并分析差异。
- 理解镜像打包和烧录验证的风险点。
- 把 QEMU 中学到的启动方法迁移到开发板上。
