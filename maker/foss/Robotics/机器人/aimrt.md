# AimRT 现代机器人运行时框架

**AimRT** 是一个面向现代机器人应用的开源运行时框架。根据项目官方说明，它基于现代 C++ 开发，重点关注轻量部署、异步编程、资源管理、配置化部署和机器人系统中的模块化开发。

你可以把 AimRT 理解为机器人应用的“运行时底座”：它不直接等同于某个具体机器人算法，而是为节点、通信、配置、日志、插件和部署提供基础设施。

:::note
AimRT 仍处于快速发展阶段。版本、模块能力和 API 可能变化较快，实际使用前应以官方文档和当前 release notes 为准。
:::

## AimRT 解决什么问题

机器人系统通常不是一个单进程程序，而是由多个模块组成：

- 传感器采集模块
- 感知算法模块
- 定位与建图模块
- 规划与控制模块
- 设备驱动模块
- 日志、监控和诊断模块

这些模块之间需要通信、调度、配置和部署。如果每个项目都从零写这些基础设施，工程复杂度会很高。AimRT 的目标就是把这类通用运行时能力抽象出来，让开发者把主要精力放在机器人业务逻辑上。

## 核心关注点

AimRT 的设计重点可以从几个方向理解：

- **现代 C++ 工程化**：适合需要高性能、低开销、强类型约束的机器人系统。
- **模块化运行时**：把机器人程序拆分为可组合、可配置的模块。
- **异步编程**：适应传感器、网络、控制和算法之间并发执行的需求。
- **部署配置**：通过配置描述模块加载、通信关系和运行参数。
- **可扩展能力**：通过插件或组件机制集成不同通信、中间件或工具链。

## 适合哪些场景

AimRT 更适合这些场景：

- 你正在开发机器人中间件、运行时或基础软件平台。
- 你需要一个比简单脚本更工程化的机器人应用框架。
- 你希望使用 C++ 构建长期维护的机器人系统。
- 你需要把多个算法模块组织成可部署、可观测的应用。
- 你正在评估 ROS/ROS 2 之外的机器人运行时方案。

如果你只是学习机器人入门，ROS/ROS 2 的资料和生态会更完整。如果你已经在做机器人系统工程，AimRT 更适合作为运行时架构选型对象来评估。

## 和 ROS/ROS 2 的关系

AimRT 和 ROS/ROS 2 关注的问题有重叠，但定位不完全相同。

ROS/ROS 2 提供了庞大的机器人生态，包括消息定义、工具链、驱动、算法包、可视化和社区教程。AimRT 更强调运行时框架和现代 C++ 工程能力。

AimRT 并不是要完全切断与现有生态的联系。官方支持通过插件兼容 ROS 2、HTTP、gRPC 等协议，因此它也可以作为现有系统渐进升级的选项，而不是只能二选一。

实际项目中，你可以按下面问题评估：

- 是否需要 ROS/ROS 2 生态中的现成算法包？
- 团队是否熟悉 C++ 工程化和运行时框架设计？
- 系统是否对部署、资源控制、异步调度有强要求？
- 是否需要与现有 ROS 2 / HTTP / gRPC 服务互通？
- 项目是否能接受新框架带来的学习和生态成本？

## 学习路径

建议按这个顺序了解 AimRT：

1. 阅读官方 README，确认项目定位和支持平台。
2. 跑通官方示例。
3. 理解模块、配置和运行时启动流程。
4. 查看通信、日志、插件等基础能力。
5. 再评估是否适合迁移到真实机器人项目中。

## 小结

AimRT 是一个面向现代机器人系统的运行时框架，适合关注高性能、模块化和工程化部署的开发者。它的价值不在于替代某一个算法包，而在于为复杂机器人应用提供更清晰的运行时组织方式。
